Notifications: hear when a run starts, succeeds, fails or runs long, in chat or by email.

## What's new
- **Notifications on a runbook.** Under **Notifications** in the editor, pick when (**Started**, **Succeeded**, **Failed**, **Running long** after a number of minutes) and where: a webhook URL or email addresses. Up to 10 per runbook.
- **Chat and webhooks.** Each event is a JSON `POST` with a one-line `text` (also as `content`), so Slack, Mattermost, Google Chat and Discord incoming webhooks show it as a message with a link to the run. The body also has the run's details and, for failures, the failed step and the last 20 output lines. Receivers that are down or answer 5xx or 429 are tried twice more.
- **Email.** Through your own SMTP server, set in a new `[email]` config section (or `OPSKILLS_EMAIL__*` variables). `opskills config` never prints the password.
- **Send a test** from the editor to check a target before relying on it.
- **On the run page:** each notification sent and whether it got through, or why not. Webhook URLs are often secret, so only their host is shown, there and in logs.
- Sending never holds up a run. Runs started by a call step don't notify; the run that called them does.
- **API:** notifications are part of the runbook. `POST /api/v1/notifications/test`, `GET /api/v1/notifications/settings` and `GET /api/v1/runs/{id}/notifications`.

See [Notifications](https://github.com/opskills-app/opskills/blob/v0.10.0/docs/runbooks.md#notifications) and [Sending email](https://github.com/opskills-app/opskills/blob/v0.10.0/docs/install.md#sending-email).

## Upgrading from v0.9.0
- **Docker:** pull `opskills/opskills:0.10.0` and re-create the container with the same volume. Nothing is sent until you add a notification. For email, add the `OPSKILLS_EMAIL__*` variables.
- **Debian/Ubuntu server:** install the new `opskills_0.10.0_*.deb`. Your config file is kept; for email, add an `[email]` section (the new default file shows one, commented out).
- **Agents:** no change needed.
- For links to runs in messages, set `server.public_url`.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.10.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.10.0/opskills_0.10.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.10.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.10.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
