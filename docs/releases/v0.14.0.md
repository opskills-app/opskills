Workspaces: a separate space for each team, with its own runbooks, runs, vault and hosts, and its own members.

## What's new
- **Workspaces.** Each workspace has its own runbooks (with their schedules, webhooks and notifications), runs, vault secrets and hosts. People see only the workspaces they belong to; everything else answers as if it didn't exist. Switch workspaces in the sidebar (under the header on phones). Everything you had is in the workspace **Default**.
- **A role per workspace.** Members are Viewers, Operators, Editors or Admins in each workspace, so the same person can edit runbooks in one team's workspace and only watch runs in another's. API tokens act with their owner's role in each workspace.
- **Server admins** manage accounts, workspaces, email settings and everyone's API tokens, read the whole audit log, and act as Admin in every workspace. They add workspaces under **Settings > Workspaces** and accounts under **Settings > Users**, with a server admin switch.
- **Members.** A workspace's Admins add existing accounts to it, change their roles and remove them under **Settings > Members**, and rename the workspace. Every member can see who else is in it.
- **Shared hosts.** A host joins the workspace its enrollment token was made in. An Admin can share it with another workspace they also administer, so one machine can serve two teams; runbooks only reach their own workspace's hosts. Renaming, tagging or removing a shared host needs Admin in all its workspaces.
- **Vault per workspace.** The same secret name can hold different values in different workspaces. The email password stays a secret of Default.
- **Audit log per workspace.** Every event names its workspace. Server admins can narrow the log to one workspace or see everything, with a **Where** column; a workspace's Admins see its own events.
- **Deploy scripts** enroll hosts into a chosen workspace: `OPSKILLS_WORKSPACE` for `deploy/enroll-hosts.sh`, `opskills_workspace` for the Ansible playbook.
- **API:** lists and creates take `?workspace=<id>`, and use Default without it, so existing scripts keep working; runbooks, runs, webhooks and hosts keep their ids, and webhook URLs don't change. New: `/workspaces` (with members, addable users and a per-workspace audit log) and `PUT`/`DELETE /hosts/{id}/workspaces/{slug}`. Changed: `GET /auth/me` returns `admin` and `workspaces` instead of `role`; users are `{"name", "admin", "workspaces": {"<id>": "<role>"}}`, and `PUT /users/{name}` takes `{"admin": true}`.

See [Workspaces](https://github.com/opskills-app/opskills/blob/v0.14.0/docs/workspaces.md).

## Upgrading from v0.13.0
- **Your data is backed up first.** On the first start, the database is copied to `opskills.redb.schema-1-backup-<time>` in the data directory, then migrated. To go back to 0.13, stop OpSkills and restore that copy.
- **Everything moves into Default.** Runbooks, runs, secrets and hosts are in the workspace Default; Admins become server admins, and everyone keeps their role in Default. Sessions, API tokens, scripts and webhook URLs keep working.
- **Docker:** pull `opskills/opskills:0.14.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.14.0_*.deb`.
- **Agents:** no change needed.
- Scripts that manage users through the API need the new user shape (see above).

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.14.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.14.0/opskills_0.14.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.14.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.14.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
