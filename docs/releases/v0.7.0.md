API tokens: let scripts, CI and other systems use OpSkills without the admin password.

## What's new
- **API tokens.** Under **Settings > API tokens**, create a token with a name and an expiry (30, 90 or 365 days, or never). It's shown once, with a ready-to-use `curl` example, and stored only as a hash.
- **Use them anywhere in the API** as `Authorization: Bearer osk_...`: start runs, read output, create enrollment tokens for new hosts, and so on. No cookie or `X-OpSkills-Request` header is needed.
- **Accountable.** Runs started with a token show it, like "admin (token CI deploy)", and the token list shows when each was last used.
- **Contained.** Revoking a token takes effect immediately, and tokens can't create other tokens or sign in.
- **`deploy/enroll-hosts.sh`** uses an API token when `OPSKILLS_TOKEN` is set, and still asks for the admin password otherwise.

See [API](https://github.com/opskills-app/opskills/blob/v0.7.0/README.md#api).

## Upgrading from v0.6.0
- **Docker:** pull `opskills/opskills:0.7.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.7.0_*.deb`.
- **Agents:** no change needed.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.7.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.7.0/opskills_0.7.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.7.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.7.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
