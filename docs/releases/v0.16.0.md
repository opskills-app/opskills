Sign in with your identity provider: Okta, Microsoft Entra ID, Google Workspace, Keycloak and others, over OpenID Connect.

## What's new
- **Sign-in with your identity provider.** A server admin sets up one provider under **Settings > Sign-in**: issuer URL (with a **Check**), client ID, and the client secret from the vault's shared secrets. The sign-in page then shows "Sign in with <label>". OpSkills does the OpenID Connect sign-in itself (authorization code with PKCE, a state bound to the browser, a nonce) and checks the ID token's signature, issuer, audience and expiry. It never trusts identity headers from a proxy.
- **Accounts.** An account is linked to the provider by the provider's own id for the person, so a changed or reused email can't take it over. On a first sign-in:
  - a user a server admin gave the same email is linked, when the provider has verified that email;
  - or, if you turn on **Create accounts on first sign-in**, people from the email domains you list get an account in no workspace, until a workspace Admin adds them;
  - anyone else sees why they can't sign in.
  With Google, listed domains must also be the person's Google Workspace domain.
- **Roles stay in OpSkills**, given by server admins and workspace Admins as before.
- **Passwords stay.** Install is unchanged: the first admin signs in with the generated password and chooses their own. Once a provider is on, **Passwords only for server admins** makes everyone else use it, so admins keep a way in if the provider is down.
- **Users** have an optional email (set when adding them, or with **Email** on the list), show when they sign in with the provider, and can be **unlinked** from it. People without a password see that they sign in with the provider.
- **Audit log:** provider sign-ins and failures with the reason, links and unlinks, email changes, and changes to the sign-in settings.
- **Website:** every feature so far, with single sign-on highlighted.
- **API:** `GET`/`PUT /settings/sign-in` and `POST /settings/sign-in/test` for server admins; `/auth/oidc/start` and `/auth/oidc/callback`; users and `GET /auth/me` gain `email`, and `GET /auth/me` gains `password` and `signs_in_with`; `PUT /users/{name}` also takes `email` and `unlink_sign_in`; `GET /system` gains `sign_in`.

See [Sign-in with your identity provider](https://github.com/opskills-app/opskills/blob/v0.16.0/docs/sign-in.md), with an [Okta walkthrough](https://github.com/opskills-app/opskills/blob/v0.16.0/docs/sign-in.md#okta-step-by-step) and notes for Entra ID, Google and Keycloak.

## Breaking changes
None. Every API change adds a field or an endpoint; `PUT /users/{name}` no longer requires `admin` but still takes it. Password sign-in only changes if you turn on **Passwords only for server admins**.

## Upgrading from v0.15.0
- **No database change.** The database stays at schema 3, so no backup is made; users read without an email or provider link until you add them. Going back to 0.15 works, but 0.15 forgets a user's email and provider link whenever it saves that user, and accounts made by a provider sign-in have no password there.
- **Docker:** pull `opskills/opskills:0.16.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.16.0_*.deb`.
- **Agents:** no change needed.
- To use sign-in with a provider, set `server.public_url` (or `OPSKILLS_SERVER__PUBLIC_URL`) if you haven't: the provider sends people back to it.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.16.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.16.0/opskills_0.16.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.16.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.16.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
