Users and roles: everyone signs in as themselves, with a role that decides what they can do.

## What's new
- **Users.** Admins add people under **Settings > Users**, each with a role. OpSkills shows a generated password once; the person chooses their own when they first sign in. Admins can change roles, reset passwords and remove users, which signs them out and revokes their API tokens.
- **Four roles.** **Viewer** sees runbooks, runs, output and hosts. **Operator** also starts, retries and cancels runs. **Editor** also edits runbooks (with their schedules, webhooks and notifications) and the vault. **Admin** also manages hosts, users, email settings and everyone's API tokens. Editors can run any command as root on the hosts a runbook targets, and the roles table says so. The app shows each person only what their role allows, and the server checks every request.
- **Every API route has an access rule.** A route without one is refused, and the tests check that every route has exactly one rule and that each rule is enforced.
- **Choose your own password at first sign-in.** The generated admin password (and any generated password) must be replaced before anything else works. Once an admin has done that, the sign-in page stops explaining where the generated password is and shows nothing about how the server was installed.
- **Personal API tokens.** Tokens belong to the user who made them and act with that user's current role, so lowering a role or removing a user takes effect on their tokens at once. Admins can see and revoke everyone's tokens.
- **Your account.** Change your password under **Settings > Your account**; your other sessions are signed out.
- **Safer upgrades.** The database now records a schema version. When a new release changes it, OpSkills first copies the database next to it (`opskills.redb.schema-<n>-backup-<time>`) and then migrates it in one step. A database from a newer release is refused instead of misread.
- **Deploy scripts** sign in as any admin: `OPSKILLS_USER` for `deploy/enroll-hosts.sh`, `opskills_user` for the Ansible playbook (both default to `admin`).
- **API:** `POST /auth/password`, `GET`/`POST /users`, `PUT`/`DELETE /users/{name}`, `POST /users/{name}/reset-password`, `GET /tokens`, `DELETE /tokens/{id}`. `GET /auth/me` and sign-in return your `role` and `must_change_password`; `GET /system` returns `setup_done`. `GET /me/tokens` now lists only your own tokens.

See [Users and roles](https://github.com/opskills-app/opskills/blob/v0.12.0/docs/users.md).

## Upgrading from v0.11.0
- **Your data is backed up first.** On the first start, the database is copied to `opskills.redb.schema-0-backup-<time>` in the data directory, then migrated. To go back to 0.11, stop OpSkills and restore that copy.
- **Nothing changes for the admin.** The single admin becomes the user `admin` with the Admin role and the same password. Sessions, API tokens and scripts that sign in as `admin` keep working.
- **Docker:** pull `opskills/opskills:0.12.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.12.0_*.deb`.
- **Agents:** no change needed.
- Then add your team under **Settings > Users**.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.12.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.12.0/opskills_0.12.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.12.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.12.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
