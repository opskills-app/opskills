Hosts over SSH: run on machines without the agent, with pinned host keys.

## What's new
- **Hosts over SSH.** Give an inventory source SSH settings (user, port, a key or password from the vault, sudo), and its hosts that no agent enrolled are reached with the OpenSSH client on the server. Everything runbooks do on agent hosts works on them: commands, copy steps, calls, rollouts, retries, live output, cancel and timeouts.
- **Host keys are pinned.** The first contact pins the keys a host presents, or checks them against keys or fingerprints its source gives, before anything is sent. Every connection then requires those keys. A changed key stops runs on that host, shows **Key changed** on the Hosts page and in the audit log, and stays refused until an Admin checks the fingerprints the host presents and accepts them.
- **Nothing secret on a command line.** The step travels on SSH's standard input, with secrets, inputs and copied file content as quoted values. Cancel and timeouts stop the step and everything it started.
- **Credentials only from the source's settings**, never from the hosts a URL or program returns, so a source can't direct a password to a host of its choosing. A host may set only its `user`, `port` and `host_keys`.
- **Hosts page:** SSH hosts with their address, key state and last connection, and a dialog to test the connection, check the keys a host presents and accept new ones. Runbooks can pick SSH hosts by name.
- **Image:** the Docker image includes the OpenSSH client; the server `.deb` recommends `openssh-client`.
- **API:** sources take `ssh`; `POST /hosts/{id}/ssh/test`, `GET /hosts/{id}/ssh/keys`, `POST /hosts/{id}/ssh/accept`; hosts gain `reach: "ssh"` and an `ssh` object; runs record each host's `ssh` settings (never the credential). Config: a new `[ssh]` section.

See [Hosts over SSH](https://github.com/opskills-app/opskills/blob/v0.18.0/docs/ssh.md).

## Breaking changes
- **`reach` has a third value, `ssh`.** Scripts that expect only `agent` or `listed` should handle it. Hosts of a source with SSH settings now report `ssh` instead of `listed`, and runs include them instead of skipping them.
- **A host's `ssh` object in a source document is now read.** Before, it was ignored like any unknown field; now it may only have `user`, `port` and `host_keys`, and anything else (or a bad value) fails the refresh with the reason, keeping the last good hosts. A document that already used an `ssh` key for other data needs to rename it.
- **New audit actions:** `host.ssh_key_pin`, `host.ssh_key_changed`, `host.ssh_key_accept`.

## Upgrading from v0.17.0
- **Database:** the first start of 0.18 upgrades it to schema 5 (pinned SSH host keys) and first copies it to `opskills.redb.schema-4-backup-<time>` in the data directory. Version 0.17 refuses a schema 5 database: to go back, stop the server and put that backup in place of `opskills.redb` (changes made since are lost).
- **Docker:** pull `opskills/opskills:0.18.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.18.0_*.deb`. To use SSH hosts, make sure `openssh-client` is installed (`apt` installs it as a recommended package).
- **Agents:** no change needed.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.18.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.18.0/opskills_0.18.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.18.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.18.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
