Vault folders and shared secrets: keep secrets in order, pick one by environment, and share a few with the teams that need them.

## What's new
- **Folders.** A secret can be in up to five folders, like `prod/db/DB_PASSWORD`. Runbooks read it as `$DB_PASSWORD`, named after its last part, so the same name can live in `prod/` and `staging/`. The Vault page browses folders with breadcrumbs and searches all of them. Existing secrets stay where they are, at the top.
- **Pick the folder with an input.** A runbook can list `{{ inputs.env }}/DB_PASSWORD` for a choice input `env`, and each run gets the secret of the chosen environment. Only choice inputs can pick a folder, and saving checks that every choice has its secret.
- **Move and rename** a secret while no runbook uses it; its value goes with it.
- **Upload a file** as a secret's value, for SSH keys and certificates, and see who changed each secret last.
- **Shared secrets.** Server admins add them on the Vault page's new **Shared** tab and share each one with chosen workspaces, or all. Runbooks there use them as `shared/smtp/SMTP_PASSWORD`; Editors see their names but can't change them. A workspace whose runbooks use a shared secret can't lose it.
- **The email password** is now picked from the shared secrets under Settings > Email. A Default secret picked before keeps working until you change it.
- **Audit log:** moves, and every change to shared secrets and their sharing.
- **API:** `PUT` and `DELETE /secrets/{name}` take a full name (`/secrets/prod/db/DB_PASSWORD`), and `PUT` moves a secret with a new `name`. New: `/shared-secrets` for server admins. Secrets have `updated_by` and `shared`.

See [Vault](https://github.com/opskills-app/opskills/blob/v0.15.0/docs/vault.md).

## Breaking changes
- `GET /secrets` now also lists the shared secrets the workspace can use, after its own, with `"shared": true` and names starting with `shared/`. Every secret in the list has `shared`. A script that changes or deletes each listed secret should skip the shared ones: the workspace API refuses them with 409, since server admins manage them under `/shared-secrets`.

## Upgrading from v0.14.0
- **Your data is backed up first.** On the first start, the database is copied to `opskills.redb.schema-2-backup-<time>` in the data directory. Nothing in it changes: this release adds a table for shared secrets, and existing secrets keep their names and encryption. To go back to 0.14, stop OpSkills and restore that copy; 0.14 refuses a database that 0.15 has opened.
- **Docker:** pull `opskills/opskills:0.15.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.15.0_*.deb`.
- **Agents:** no change needed.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.15.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.15.0/opskills_0.15.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.15.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.15.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
