Inventory: hosts and attributes from a list, a URL or a program, and tags by rules.

## What's new
- **Attributes.** Hosts have attributes like `env: prod` or `region: eu-west-1`. Admins set them on enrolled hosts (**Hosts**, the pencil icon), and inventory sources add them. An Admin's value wins over a source's.
- **Filters and commands use them.** `env:prod`, `region:eu-*` or `!team:payments` work in runbook targets, tag rules and the hosts search. `{{ host.attr.env }}` in a command becomes the host's value as one quoted shell word (empty when the host doesn't have it), and a run keeps the values it started with, also for retries.
- **Tag rules.** Per workspace: hosts matching a filter get tags, like `os:debian*` gets `debian`. Runbooks that target a rule's tag keep up as hosts come and go.
- **Inventory sources.** A workspace's Admins add sources under **Hosts > Inventory sources**:
  - **List:** hosts written in OpSkills.
  - **URL:** a JSON document fetched on an interval, with an optional header from the vault, like your CMDB or service registry. Redirects aren't followed, so the header never goes to another server.
  - **Program:** a program on the server that prints hosts, with settings as `OPSKILLS_CONFIG_*` variables and vault secrets as variables. Only server admins can add or change one, since it runs code on the server. This is the format inventory plugins will use.
- **Source hosts and enrolled hosts.** A source host whose hostname matches an enrolled host adds its tags and attributes to that host. Other source hosts are **listed**: they show on the Hosts page, filters and rules see them, and runs skip them with a note on the run page until the agent is installed.
- **Failures are visible.** A source that fails keeps the hosts of its last good refresh, shows **Failing** with the error, and marks its hosts as possibly out of date. A source that suddenly lists no hosts keeps the old ones until an Admin accepts the empty list. Each source refreshes on its interval (default 5 minutes), when it's saved, and on **Refresh now**.
- **Audit log:** sources added, changed and removed, the first failure and the recovery, hosts a source added or removed, tag rule changes, and host attributes.
- **API:** `GET`, `POST /inventory/sources`, `GET`, `PUT`, `DELETE /inventory/sources/{id}`, `POST /inventory/sources/{id}/refresh`, `PUT /workspaces/{slug}/tag-rules`; `PUT /hosts/{id}` takes `attributes`; hosts gain `attributes`, `reach`, `sources`, `rule_tags`, `stale`, `own_tags` and `own_attributes`; runs gain `hosts[].attributes` and `skipped_hosts`; workspaces gain `tag_rules`.

See [Inventory](https://github.com/opskills-app/opskills/blob/v0.17.0/docs/inventory.md).

## Breaking changes
Nothing changes until you add an inventory source, a tag rule or an attribute, except the filter keys below.
- **Host filters accept any attribute name.** A key that isn't `tags`, `name`, `hostname`, `os` or `arch` used to be refused (400); now it's an attribute, so a misspelled key like `nmae:web` matches no host instead of failing. Keys that can't be attribute names, like `-env` or `e!nv`, are still refused.
- **`GET /hosts` can list hosts without an agent.** With a source, it includes hosts only the source lists (`"reach": "listed"`). They have no OS, architecture or agent version, and `PUT`/`DELETE /hosts/{id}` answer 404 for them. Scripts that act on every listed host should skip those.
- **`tags` and `attributes` on a host include what sources and tag rules add.** A script that reads a host's `tags` and writes them back with `PUT /hosts/{id}` would save those as the host's own tags. Start from `own_tags` (and `own_attributes`) instead.
- **Runbook targets see source and rule tags.** A runbook targeting a tag also runs on enrolled hosts that get the tag from a source or a rule.
- **`{{ host.attr.<key> }}` in a command is now replaced.** Before, it was left as text.
- **New audit actions:** `inventory_source.create`, `inventory_source.update`, `inventory_source.delete`, `inventory_source.refresh_failed`, `inventory_source.recovered`, `inventory_source.hosts_change` and `workspace.tag_rules`. `host.update` details also list attributes.

## Upgrading from v0.16.0
- **Database:** the first start of 0.17 upgrades it to schema 4 (inventory tables) and first copies it to `opskills.redb.schema-3-backup-<time>` in the data directory. Version 0.16 refuses a schema 4 database: to go back, stop the server and put that backup in place of `opskills.redb` (changes made since are lost).
- **Docker:** pull `opskills/opskills:0.17.0` and re-create the container with the same volume.
- **Debian/Ubuntu server:** install the new `opskills_0.17.0_*.deb`.
- **Agents:** no change needed.

## Install the server

**Docker** (`linux/amd64`, `linux/arm64`):

```bash
docker run -d --name opskills -p 127.0.0.1:8080:8080 \
  -v opskills-data:/var/lib/opskills --restart unless-stopped \
  opskills/opskills:0.17.0
docker logs opskills 2>&1 | grep 'Admin password'
```

**Debian 12+ / Ubuntu 22.04+:**

```bash
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.17.0/opskills_0.17.0_amd64.deb
curl -LO https://github.com/opskills-app/opskills/releases/download/v0.17.0/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./opskills_0.17.0_amd64.deb
sudo systemctl start opskills
sudo journalctl -u opskills | grep 'Admin password'
```
